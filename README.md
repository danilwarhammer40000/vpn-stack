# vpn-stack

Один установщик для чистого Ubuntu 24.04: **nginx на :80**, **TrustTunnel на :443**, **Xray (VLESS + XHTTP) за CDN** и поверх них **TrustPanel** (Telegram-бот), который управляет обоими VPN.

```
                       ┌─ :443 ──> TrustTunnel (напрямую, TT_DOMAIN)
Интернет ──────────────┤
                       └─ :80  ──> nginx ─┬─ /.well-known/acme-challenge/ ──> certbot (сертификат для TT_DOMAIN)
CDN ── XRAY_DOMAIN ────────────────────────┤
                                            ├─ /api/v1/sync ──> Xray 127.0.0.1:10085
                                            └─ всё остальное ──> 404
```

Порт 80 делят три задачи: CDN приходит на него за Xray, Let's Encrypt проверяет по нему домен TrustTunnel (HTTP-01, и при установке, и при каждом продлении), всё остальное получает 404. Поэтому certbot работает в режиме `--webroot`, а не `--standalone`.

## Что переживает переустановку сервера

| Что | Где лежит | Попадает в бэкап бота |
|---|---|---|
| Пользователи, пароли, сроки, UUID для Xray | `data/users.json` | да (уже было) |
| Всё про Xray: ключ сервера (`vlessenc`), параметры ссылок, кому включён Xray и их UUID | `data/xray.json` (отдельный файл) | **да (новое)** |
| Настройки TrustTunnel (`vpn.toml`, `hosts.toml`, `rules.toml`) | `data/tt_config.json` (снимок) | **да (новое)** |
| Триалы, настройки, автопродление | `data/*.json` | да (уже было) |
| `credentials.toml` TrustTunnel | собирается из `users.json` | не нужен |
| Сертификат Let's Encrypt | выпускается заново для того же домена | не нужен |

Раздел `server` в `xray.json` важен: если сервер получит новую пару ключей, **все ранее выданные ссылки Xray перестанут работать**. Установщик никогда не перегенерирует существующий ключ, а при каждой синхронизации панель приводит конфиг Xray к состоянию из `xray.json` (ключ, путь, padding), поэтому восстановление базы через бота возвращает старый ключ само.

Снимок TrustTunnel обновляется перед каждым плановым бэкапом (drop-in для `trustpanel-backup.service`). Кнопка «📤 Выгрузить сейчас» снимок не обновляет: если вы меняли настройки TrustTunnel руками, сначала выполните `python3 /opt/vpn-stack/tools/snapshot_tt.py save`.

## Установка с нуля

Подготовьте: A-запись `TT_DOMAIN` на IP сервера (**не** через CDN), домен для Xray, подключённый к CDN (origin = этот сервер, HTTP, порт 80, кэш выключен), IP узла CDN.

```bash
git clone <ваш-репозиторий> /root/vpn-stack && cd /root/vpn-stack
sudo ./install.sh                  # спросит всё нужное
# или без вопросов:
cp stack.env.example stack.env && nano stack.env
sudo ./install.sh --answers stack.env
```

Единственное интерактивное место, если нет бэкапа: мастер TrustTunnel (`setup_wizard`). Установщик заранее напечатает, что отвечать: адрес `0.0.0.0:443`, любой временный пользователь, сертификат «Provide path to existing certificate» с путями certbot. Пользователей потом пересоберёт панель.

Добавьте `--firewall`, чтобы установщик настроил `ufw` (SSH, 80/tcp, 443/tcp, 443/udp).

## Восстановление на новом сервере

1. Найдите последний zip, который присылал бот (`trustpanel_backup_….zip`).
2. Положите на новый сервер и запустите:

```bash
sudo ./install.sh --restore trustpanel_backup_20261003_0300.zip
```

Установщик проверит архив (допустимы только известные файлы, `users.json` должен иметь правильную форму), восстановит базу и снимок TrustTunnel (**мастер не запускается**), вернёт прежний ключ Xray и сразу пересоберёт credentials и клиентов. Клиентам ничего не меняют: их ссылки продолжают работать. Домены и IP узла CDN нужно будет указать заново; домен Xray и IP узла берутся из архива как значения по умолчанию.

Если вы уже поставили чистый сервер без `--restore`, можно восстановиться из бота («🗄 База данных» → «📥 Загрузить БД»). Ключ Xray вернётся при следующей синхронизации. Снимок TrustTunnel в этом случае не применяется (он нужен только установщику).

## Xray в панели: только для админа

- **Данные Xray лежат в своём файле `data/xray.json`**, отдельно от `users.json`: раздел `server` (ключ и параметры ссылок) и раздел `clients` (кому включён Xray и UUID). `users.json` Xray не меняет вообще. Файл с правами 600, входит в бэкап бота.
- **Клиентам Xray не виден.** Ссылка показывается только админу: в карточке пользователя кнопка **🛰 Xray** и рядом со ссылкой в «🔗 Get link». В клиентском меню («Моя ссылка») Xray нет.
- **Включается по одному.** По умолчанию Xray не получает никто. Админ открывает карточку пользователя → «🛰 Xray» → «✅ Включить», и сразу получает ссылку. Дальше доступны: «🔗 Показать ссылку», «🚫 Выключить» (UUID сохраняется, при повторном включении ссылка та же), «🔄 Выдать новую ссылку» (с подтверждением, старая перестаёт работать).
- **Срок подписки общий.** Включённый в `xray.json` клиент попадает в Xray, только пока его запись в `users.json` активна и не истекла (неразбираемая дата = нет доступа). Истёк срок: Xray отключается сам, а выбор админа сохраняется и вернётся после продления.
- Клиенты, созданные панелью, помечены в конфиге Xray как `tp:<имя>`. Клиенты, добавленные в конфиг вручную, не трогаются.
- Конфиг сначала проверяется `xray run -test`, потом заменяет рабочий (копия `config.json.bak`), при сбое запуска откатывается. Перезапуск только если конфиг изменился или сервис оказался остановлен. Если применить изменение не удалось, бот пишет админу причину.
- Повреждённый `xray.json` никогда не перезаписывается: синхронизация ничего не меняет, а кнопки сообщают об ошибке.
- Если раньше UUID лежали прямо в `users.json` (первая версия функции), они один раз переносятся в `xray.json`.

## Ручной тариф клиента

Карточка пользователя → **💰 Тариф** (только админ, только у ведущих и одиночных: у ведомого тариф определяет ведущий). Можно задать фиксированную цену ₽/мес (целое 1–100000) или вернуть автоматическую.

- Ручная цена **полностью заменяет** автоматическую (базовая цена и наценка за доп. ссылки) везде, где панель считает цену: экран оплаты, проверка чеков, напоминания.
- Срок доступа не меняется. Новая цена действует **со следующего продления**: панель одновременно сдвигает `last_renewal_rate`, чтобы клиенту не предлагали «доплатить разницу» за уже оплаченное время.
- Срок по-прежнему правится кнопкой «⏳ Extend» (там же есть ручной ввод даты).
- Клиенту уведомление не отправляется.

## MAX-бот заморожен

Установщик не спрашивает токен MAX и отвечает пустым значением на этот вопрос панели. Если на сервере уже стоит `trustpanel-max-bot.service`, он останавливается и отключается. Код в репозитории не удалён: чтобы вернуть, включите службу и задайте токен в `.env`.

## Состав репозитория

| Путь | Назначение |
|---|---|
| `install.sh` | единый установщик (идемпотентный: повторный запуск пропускает сделанное) |
| `templates/nginx-stack.conf.tpl` | конфиг nginx: ACME + путь Xray + 404 |
| `tools/xray_setup.py` | запись раздела `server` в `xray.json` (существующий ключ не перезаписывается, `clients` не трогается) и базовый конфиг Xray |
| `tools/snapshot_tt.py` | снимок и восстановление настроек TrustTunnel (JSON) |
| `overlay/` | модули `core/xray.py`, `core/tariff.py`, обработчики `admin_xray.py` и `admin_tariff.py`, тесты и патч `apply_xray_patch.py` |
| `tests/test_install.sh` | тесты вспомогательных функций установщика |

`overlay/` нужен, пока этот код не закоммичен в сам репозиторий панели. Рекомендую закоммитить его туда (новые файлы из `overlay/` и результат `apply_xray_patch.py`, он правит `core/paths.py`, `core/service.py`, `core/payment.py`, `bot/bot.py`, `bot/handlers/list_users.py`): тогда `git pull` в `deploy.sh` не будет затирать правки, а установщик увидит готовый `core/xray.py` и просто пропустит этот шаг.

## Проверка

```bash
bash tests/test_install.sh                       # функции установщика
cd /opt/trustpanel && venv/bin/pytest tests/ -v  # включая tests/test_xray.py
sudo ./install.sh --check                        # статус служб и портов
```

## Известные ограничения

- Мастер TrustTunnel запускается интерактивно: формат его конфигов я не генерирую сам, чтобы не гадать. Поэтому для воспроизводимости и нужен снимок.
- Установщик панели (`install.sh` из tg-trust) получает ответы через stdin в порядке своих вопросов. Если вы измените его вопросы, установщик стека это заметит (проверка `.env`) и остановится.
- Бэкап теперь содержит приватный ключ Xray и пароли пользователей и уходит в Telegram. Храните zip как секрет. Шифрование архива паролем можно добавить отдельно.
- Сертификат TrustTunnel продлевается certbot-таймером, после продления службу перезапускает deploy-hook. Установщик проверяет это через `certbot renew --dry-run`.
- Xray и ручной тариф управляются только из карточки пользователя. Отдельного списка «у кого включён Xray» пока нет.
- Записи в `xray.json` удалённых пользователей остаются (они ни на что не влияют). Автоочистки нет: при временной порче `users.json` она могла бы стереть настройки.
